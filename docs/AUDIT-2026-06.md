plan (`docs/RE-INFRASTRUCTURE-PLAN.md`) still holds: derive specs from the

## 5. Loose ends found in the 2026-06-04 deep audit (don't forget)

Nothing here is a live outage; these are the gaps a thorough sweep surfaced so
they're tracked. Full detail + fixes live in `docs/PHASES-INTELLIGENCE.md` § Phase 29.

- **Scale / concurrency.** 10–15 concurrent users: safe today. **100–200: not until
  DB connection pooling is added** (Railway PG is a direct connection; Prisma's
  default pool exhausts). Fix = Prisma Accelerate or a PgBouncer sidecar + cache the
  `force-dynamic` dashboard (~22 queries/load). Keep `numReplicas = 1` until the
  in-memory realtime store moves to Redis. One stray pool in `app/api/seed/route.ts`.
- **Dead code.** `lib/toast.client.ts` and `lib/alertEvaluator.ts` (476 lines,
  duplicates `lib/alertEngine.ts`) are unreferenced — delete.
- **Admin console.** Correction: the 13 ERP back-office routes (`/admin/imports`,
  `/admin/products`, `/admin/journal`, …) are **NOT dead** — they live under
  `app/(app)/admin/*` (operator shell) and render fine; the `/admin/system` links
  resolve. The real gap is they have no single Orrery hub ("The Core" — Phase 27b).
  Separately, `/admin/db` (the cyan Data Browser) is not in the admin top rail.
- **Phase 22** is effectively **shipped** (verifier wired into the narrator,
  telemetry persisted on `Narrative`, badges rendered) — the doc's old "still to
  land" was stale; now corrected.
- **Phase 10 weekly self-tuning is dormant in prod** — `/api/brain/cron` exists but
  no scheduler fires it (Railway has no built-in cron). On-demand "Run analysis"
  works. (Already noted in P2 "Wire up the Brain cron.")
- ✅ **`.env.railway.template`** — file exists at repo root; reference is valid.
- **Zero `app/`/`components/` tests** — 55 suites all live under `lib/`. A smoke-test
  floor for the 25 API routes is the highest-leverage quality add (Phase 29 §5).
